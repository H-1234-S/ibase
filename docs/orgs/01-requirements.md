# 01 产品需求与范围

## 1. 背景

ibase 是类 Supabase 的 BaaS 平台。现有 Auth 已解决“用户是谁”，下一层核心业务边界是“用户属于哪些组织，以及在每个组织中可以做什么”。组织是项目及相关资源的主要归属边界，成员关系是组织级访问资格，邀请是受控的加入方式。

本功能不得重写现有 Auth；必须复用注册、邮箱验证码、登录、会话刷新、统一请求和错误处理。

## 2. 产品目标

1. 普通注册用户在没有待恢复邀请时，可以创建第一个或后续组织。
2. 创建者自动成为 admin，组织与初始 Membership 在同一事务中成立。
3. admin 可以通过邮箱邀请 member，并管理待处理、已接受、已撤销和已过期邀请。
4. 已注册及未注册用户都能在安全校验后接受邀请；未注册用户沿用 Auth 邮箱验证。
5. 用户可切换组织，并在 Dashboard 查看组织、成员及自身角色。
6. admin 可修改角色、移除成员、撤销/重发邀请和删除组织。
7. 所有权限、数据隔离、最后 admin 保护和邀请消费均由服务端保证。
8. 所有页面具备加载、空、成功、失败、权限不足、登录失效和重复提交反馈。

## 3. 用户与职责

| 用户           | 核心诉求                   | 第一版能力                                                           |
| -------------- | -------------------------- | -------------------------------------------------------------------- |
| 无组织用户     | 创建组织或接受邀请进入团队 | 创建组织、完成邀请注册/登录恢复                                      |
| 组织 admin     | 管理团队和邀请             | 查看组织/成员、邀请、角色管理、移除成员、删除组织,在当下组织创建项目 |
| 组织 member    | 使用组织资源               | 查看所属组织/成员、切换组织；无管理权限                              |
| 被邀请的新用户 | 安全加入指定组织           | 验证邮箱并注册后接受 member 邀请，无需先创建组织                     |

## 4. 功能范围

### 4.1 本版包含

- 组织创建、列表、详情和当前角色。
- 多组织成员关系与组织切换。
- 成员列表：邮箱、显示名、角色、加入时间。
- 邀请创建、列表、详情预览、重发、撤销、过期后重新邀请。
- 已登录、未登录、未注册三种邀请接受路径。
- admin/member 两种角色及最后 admin 保护。
- 移除成员与数据库范围内的组织删除。
- 服务端组织级授权、事务、唯一约束、并发保护、限流和审计。
- 关键流程自动化测试与 Auth 回归测试。

### 4.2 本版不包含

- 组织更名、slug 自定义、组织头像和转让永久 owner。
- owner 或自定义角色、通过邀请直接授予 admin。
- 项目 CRUD 和项目级角色模型的具体实现。
- 外部数据库、存储对象、API Key、日志或云任务的异步清理实现。
- 批量邀请、邀请链接公开加入、域名自动加入、SSO 和 SCIM。
- 组织恢复或回收站；当前数据库内删除为最终删除。

## 5. 核心业务流程

### 5.1 普通注册与创建组织

注册并完成 Auth 邮箱验证 → 无有效邀请恢复上下文 → 创建组织页 → 服务端事务创建 Organization + admin Membership → 进入新组织 Dashboard → 成功反馈。

### 5.2 邀请已注册用户

admin 输入邮箱 → 服务端检查 admin、成员和重复邀请 → 创建仅含 member 角色的邀请 → 发送邮件 → 用户打开邀请链接 → 登录或确认当前账号 → 校验邮箱匹配 → 事务创建 Membership 并接受邀请 → 进入被邀请组织。

### 5.3 邀请未注册用户

打开邀请链接 → 识别目标邮箱尚未注册 → 进入注册页并保留邀请上下文 → 复用 Auth 验证码验证同一邮箱 → 注册成功 → 重新校验邀请 → 接受邀请 → 进入被邀请组织，不经过强制创建组织页。

### 5.4 成员与组织管理

admin 修改角色或移除成员 → 服务端在事务内锁定组织并重检权限及 admin 数量 → 提交变更 → 后续请求立即按新 Membership 授权。删除组织需明确二次确认，当前仅删除数据库范围内的目标组织及其级联数据。

## 6. 产品验收标准

1. 普通注册后无组织用户只能进入合理的初始化或公开流程，不能伪造组织 ID 进入他人组织。
2. 创建组织后仅产生一个组织和一条创建者 admin Membership。
3. 一个用户可加入多个组织，并在不同组织中拥有不同角色；同一组织内无重复 Membership。
4. member 无法通过界面或直接调用 API 执行 admin 操作。
5. 未注册被邀请者完成现有邮箱验证后可恢复邀请，不被强制创建自己的组织。
6. 邀请邮箱与登录邮箱不一致、邀请过期/撤销/无效时均不能接受，并有可操作的错误提示。
7. 同一邀请并发接受最多产生一条 Membership 和一次有效状态迁移。
8. 最后一位 admin 不能被降级或移除；移除成员不删除全局用户。
9. 删除目标组织不影响其他组织、全局用户或未来不属于删除范围的数据。
10. 页面刷新后会话与组织上下文可恢复；任何缓存的组织选择都在服务端重新验证。
11. 现有 Auth 注册、登录、刷新和退出功能无回归。
12. 不把规划中的项目清理、外部资源清理或测试能力描述为已实现。

## 7. 成功反馈原则

- 创建组织、邀请、接受邀请、角色修改、移除和删除均有明确成功反馈。
- 管理操作失败使用现有 sonner toast；字段错误靠近字段，邀请页面级异常展示原因及下一步入口。
- 按钮在请求中禁用并显示进度；服务端仍负责幂等与并发保护，前端防重复提交不是一致性依据。
