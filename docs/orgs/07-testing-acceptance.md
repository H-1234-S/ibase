# 07 测试计划与验收清单

## 1. 测试原则

- 先写能复现缺陷或违反业务不变量的失败测试，再实现到通过；不能只写永远成功的样例。
- 单元测试放在 `apps/api/tests/`，目录镜像 `src/`，每个文件只测试对应源文件。
- 数据库约束、事务和并发必须用真实 PostgreSQL 集成/e2e 验证，不能仅靠 mock 推断。
- Redis 限流、邀请状态及 Auth 验证码恢复使用可控测试环境；SMTP 使用可注入替身模拟成功和失败。
- 不使用正则匹配样式文件作为测试；前端通过组件行为和工具链验证。
- 不用单元测试代替真实并发、数据库迁移或浏览器关键流程验证。

## 2. 单元测试

### 2.1 组织与成员服务

- 名称 trim、空名称、控制字符、1/80/81 字符边界。
- 创建组织成功时创建者为 admin；任一步失败事务回滚。
- 同用户可加入多个组织，不同组织可有不同角色。
- 非成员不能读取组织或成员；member 不能执行任何 admin 操作。
- 目标 membershipId 不属于路由 orgId 时拒绝。
- admin 可升级/降级成员，变更后新请求立即使用新角色。
- 最后 admin 降级、被移除、移除自己均被拒绝。
- 有多个 admin 时允许自己降级/移除。
- 移除成员不删除 User，不影响该用户其他组织 Membership。

### 2.2 邀请服务

- 邮箱规范化、无效邮箱、邀请已是成员的用户。
- 客户端提交 admin role 不会被授予 admin。
- 有效 pending 重复创建返回一致错误；可执行受控重发。
- revoked/expired 可创建新邀请，新 token 与原 token 不同。
- token 只存摘要，响应和日志不包含 tokenHash/原始 token。
- 过期、撤销、已接受、无效邀请不能接受。
- 邮箱不匹配及未完成邮箱验证的用户不能接受。
- 已是成员时接受幂等，不产生重复 Membership。
- 首次邮件失败执行补偿，不留下有效 pending；重发失败保留原有效邀请。
- 首次发送失败补偿失败有可观测错误，不向客户端返回成功。
- 重发不延长原有效期，过期后不能重发。

### 2.3 授权与 DTO

- 未认证、无 Origin/CSRF 标记的写请求被拒绝。
- orgId、membershipId、invitationId、email、role 的 DTO 边界。
- 非成员组织访问不泄露不必要的内部详情。
- 所有错误码、HTTP 状态和统一错误信封正确。

## 3. 数据库集成与并发测试

| 场景                         | 必须证明的结果                                          |
| ---------------------------- | ------------------------------------------------------- |
| 并发创建同一组织/邮箱邀请    | 最多一条有效 pending                                    |
| 并发接受同一邀请             | 最多一条 Membership、最多一次有效接受迁移               |
| 同一用户重复接受             | 幂等结果，无重复成员或重复副作用                        |
| 两个 admin 同时互相/自身降级 | 最终 admin 数始终 ≥ 1，一个操作应失败                   |
| admin 移除与角色变更并发     | 不出现零 admin、 phantom Membership 或越权              |
| 接受邀请与移除成员竞争       | 唯一约束成立，最终权限与数据库一致                      |
| 并发删除组织                 | 仅一个实际删除，最终无目标组织级联数据，无半状态        |
| 删除组织                     | 不影响其他组织、用户、Auth 会话和其他组织数据           |
| 数据库唯一约束               | 即使服务层检查被绕过，也无法写入重复 pending/Membership |

并发测试使用真实事务和独立数据库连接，不能只用单连接顺序调用模拟。

## 4. API e2e 流程

### 4.1 普通用户

1. 复用 Auth 发送验证码并注册。
2. 无邀请时查询组织为空，进入创建组织流程。
3. 创建组织，验证当前角色 admin 和成员数 1。
4. 创建第二个组织，验证组织列表和角色隔离。
5. 刷新会话后组织数据仍按当前用户返回。

### 4.2 已注册用户邀请

admin A 邀请已注册 B → B 预览 → 未登录登录恢复 → 接受 → 成为 member → B 无管理权限 → A 提升 B 为 admin → B 获得管理权限 → 降级/移除按规则生效。

### 4.3 未注册用户邀请

admin A 邀请新邮箱 → 打开邀请 → 进入注册 → 复用 Auth 验证码完成注册 → 恢复并接受 → 直接获得目标组织 Membership → 不创建其他组织。

### 4.4 异常邀请

分别覆盖邮箱不匹配、切换账号、注册中过期/撤销、无效 token、重复消费、重发、撤销、过期重邀、邮件失败和限流。

## 5. 前端测试与手工验收

Web 当前没有组件测试运行器。实现关键路由和组件行为测试前，应引入与现有 React/Next 兼容的最小测试工具，或明确将对应场景纳入可自动执行的浏览器 e2e；不能只做静态页面人工检查。

至少覆盖：

- 创建组织表单校验、busy、成功跳转、失败 toast 和重复点击。
- Dashboard 加载、空、失败重试和权限不足。
- 组织切换、最近组织失效、页面刷新恢复、退出后清空上下文。
- member 不见管理入口，直接访问管理路由仍被服务端结果阻止。
- 角色修改、移除确认、最后 admin 错误反馈。
- 删除组织名称确认、取消、失败保留、成功跳转。
- 邀请已登录/未登录/未注册恢复，邮箱不匹配和各类失效状态。
- 普通注册与邀请注册路由决策不同。
- token 不出现在分析事件、应用日志、toast 或持久化 Web Storage。

## 6. 迁移验收

- 空数据库可执行全部迁移。
- 含 Auth 数据的数据库升级后用户、会话、Refresh Token 数据保持完整。
- Drizzle Schema、生成 SQL 与实际数据库一致。
- 唯一、部分唯一、外键、级联和索引真实存在。
- 迁移后不破坏现有 Auth 注册、登录、刷新、退出和邮箱验证码。

## 7. 工程质量命令

实现阶段至少执行并记录实际结果：

```bash
pnpm --filter api test
pnpm --filter api test:e2e
pnpm --filter api check-types
pnpm --filter api lint
pnpm --filter web check-types
pnpm --filter web lint
pnpm --filter web build
pnpm check-types
pnpm lint
pnpm build
```

根目录 `pnpm db:generate` / `pnpm db:migrate` 用于 Drizzle 迁移；测试应使用隔离数据库，不能对开发或生产数据直接试迁移。

- [ ] API 响应、日志和数据库均无原始邀请 token 或敏感凭证。
- [ ] 邮件失败、限流和超时路径经过模拟。
- [ ] 非成员/member 直接调用 API 的越权测试通过。
- [ ] 最后 admin 和并发安全经过真实数据库验证。
- [ ] 删除范围与前端文案一致，没有虚构外部资源清理。
- [ ] 未提交真实密钥、SMTP 授权码、生产配置或未处理的关键 TODO。
